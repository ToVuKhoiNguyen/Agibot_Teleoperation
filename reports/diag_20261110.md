### 1. Speed Limit Chain (End-to-End Cascade)

`[PROFILE] Active Profile: NORMAL (0.30 rad/s) | Steady error v*tau: 0.030 rad (tau assumed 0.10s)`

### 2. Configuration & Default Fallback Analysis
- `config/tau_id.json` exists with $\tau_{max} = 0.157$ s ($\tau_{mean} = 0.138$ s).
- However, `main.py:228-236` omits passing `gate_mode=args.gate_mode` into `UnifiedTeleopApp`, leaving `gate_mode` defaulted to `"legacy"`.
- In `legacy` mode (`mirror_limiter.py:55-57`), `scale_const = 0.05`, which caps $v_{cap} = 0.7 \times 0.05 / 0.157 = 0.2229$ rad/s.
- If `config/tau_id.json` were absent, `mirror_limiter.py:59` would silently fall back to `SPEED_PROFILES["slow"][0] = 0.20$ rad/s.
- Active default profile is `normal`, but its effective speed is clamped down to $0.2229$ rad/s.

### 3. Theoretical Max Joint Speed & Creeping Mechanism
- **Theoretical Max Joint Speed**: $v_{max} = \min(0.30, 0.50, 0.2229) = 0.2229$ rad/s ($\approx 12.8^\circ$/s).
- **Tightest Bottleneck**: `MirrorLimiter` ($0.2229$ rad/s in legacy mode) combined with `Soft Back-Off` (down to $0.0223$ rad/s when lead exceeds $35$ mrad).
- **Cascade Step-Response Delay**: Five cascading low-pass and rate-limiter stages stack in series (Cartesian follower $\to$ IK shadow limiter $\to$ MirrorLimiter $\to$ SafetyLayer $\to$ Orin rate limiter).
- **Why Creeping Occurs**:
  1. The Web UI (`scene.js:83-113`) does not notify the backend on mouse-up / drag completion. `app.gizmo_active_l` remains permanently `True`.
  2. A sudden mouse drag of $0.2$ m causes a target displacement of $\approx 0.8$ rad in joint space.
  3. Because the rate limiter allows only $0.00446$ rad per tick ($0.2229$ rad/s at 50 Hz), the command buffer trickles forward for $0.8 / 0.2229 \approx 3.6$ seconds after mouse release.
  4. In `backend == "sim"`, `CriticallyDampedFollower` and `ik_dispatcher` run every tick continuously while `gizmo_active_l` remains `True`.

### 4. Log Analysis (`logs/real_20261110_195601.jsonl`, 14,274 ticks)
- Peak joint step $|dq| = 0.00600$ rad/tick ($0.30$ rad/s at 50 Hz).
- Peak Cartesian target velocity: $0.3017$ rad/s.
- p95 tracking error: $0.0099$ rad ($9.9$ mrad).
- Max tracking error: $0.0544$ rad (triggered `hard_deviation_gate` FAULT latch).
- Soft back-off active ($|lead| > 0.035$ rad): 104 ticks ($0.73\%$ of session).
- Time from gizmo stop to joint velocity $< 0.003$ rad/s: $2.4$ to $3.8$ s on large displacements.

## Issue 2: Gripper Close/Open Does Nothing in Sim and Hardware

### 1. End-to-End Signal Trace
1. **Web UI Event**: User clicks gripper buttons or drags slider $\to$ sends JSON `{cmd: 'hand', arm: 'left', action: 'close'}`.
2. **State Storage**: Handled in `teleop/app/cmd_hands.py:34-80`, updating `app.target_curls_l` and `app.hand_closure_l = 1.0`.
3. **Retargeting & Safety**: In `teleop/app/control_loop.py:101-125`, retargeted via `AgibotHandRetargeting` into 6-DOF joint vector `cand_hand_l`, safety filtered into `app.last_hand_cmd_left`.
4. **Dispatch**: In `teleop/app/sync_manager.py:98-102`, packs 12-vector `h12 = np.concatenate([app.last_hand_cmd_left, app.last_hand_cmd_right])` and invokes `app.robot_safety.send_hand(h12)`.
5. **SafetyLayer**: Calls `self.backend.send_hand(clamped_h)` in `teleop/robot/safety_layer.py:247`.

### 2. Breakpoints & Root Causes
- **Breakpoint 1 (UDP Backend)**: In `teleop/robot/udp_backend.py:181`:
  ```python
  def send_hand(self, h12: np.ndarray) -> None:
      pass  # Complete NO-OP
  ```
  In `udp_backend.py:154-158`, `_send_packet_now()` constructs the packet with keys `{"seq", "t", "session_id", "proto_ver", "q"}` without any `"hand"` key.
- **Loopback Sample Packet**:

  *(Confirmed: `"hand"` key is completely absent).*
- **Breakpoint 2 (Orin Receiver)**: In `scripts/arm_teleop_rx.py`, the node only instantiates `/motion/control/arm_joint_command`. There is no publisher for `/motion/control/hand_joint_command`.
- **Breakpoint 3 (Sim Mode)**: In `teleop/app/sync_manager.py:85`, `app.env.set_arm_commands` is called when `is_real=True`, but `app.env.set_hand_commands` is omitted. In pure sim mode with `hold_arms=True` (`mujoco_env.py:211-219`), `self.data.ctrl` is updated only for arms; hand joint positions are never integrated by `mj_forward`.

## Issue 3: Real Hand Closed (Fist) but UI Shows Open Hand

### 1. Signal Path & Root Causes
- **Sim Twin Pose Source**: Web UI renders hand links using `self.data.xpos` and `self.data.xquat` streamed from `app.env.get_visual_body_poses()` (`teleop/simulation/mujoco_env.py:188-201`), computed from `self.data.qpos`.
- **Telemetry Feedback Hardcoded to Zeros**: In `teleop/robot/udp_backend.py:183-195`:
  ```python
  def read_state(self) -> Tuple[Optional[np.ndarray], Optional[np.ndarray]]:
      with self._lock:
          q_arm = self._last_q14.copy() if self._last_q14 is not None else None
          q_hand = np.zeros(12, dtype=np.float64)  # Hardcoded zeros!
      return q_arm, q_hand
  ```
- **Orin Receiver State Omission**: `scripts/arm_teleop_rx.py` does not subscribe to `/motion/control/hand_joint_state`. Feedback packets only include arm joints `{"t", "q", "profile"}`.
- **Convention & Scale Mismatch**:
  - Real robot hardware (`a2_driver`): integer range `0` (open) to `2000` (closed fist), capped $\le 800$ in ROS2 backend.
  - MuJoCo Sim: radians (`thumb_swing` $[0, 2.286]$, `index_1` $[0, 1.70]$).
  - Telemetry default is $0.0$ rad, corresponding to a completely open hand. Because feedback is never populated or mirrored into `self.data.qpos`, the UI twin stays permanently open.

## Issue 4: Robot Legs Sunk Below Ground in Sim and UI

### 1. Geometric & Kinematic Cause
- **Fixed Base Height**: In `assets/agibot_a2_ultra/mjcf/a2_ultra.xml:124`:
  `<body name="base_link" pos="0 0 0.93">`
- **Leg Length**: From `base_link` down through hip, knee, ankle, and toe (`idx06_left_toe_roll_link` / `idx12_right_toe_roll_link`) with zero joint angles, the kinematic vertical leg length is $0.9618$ m.
- **Floor Penetration**:
  $$z_{toe} = z_{base} - L_{leg} = 0.9300 - 0.9618 = -0.0318\text{ m} = -31.8\text{ mm}$$
  The feet penetrate $31.8$ mm into the ground plane ($z = 0$).

### 2. Enforced Leg Zeroing in Code
- In `teleop/simulation/mujoco_env.py:216-218`, `225-227`, and `234-236`:
  ```python
  if hasattr(self, "non_manip_qpos_indices"):
      self.data.qpos[self.non_manip_qpos_indices] = 0.0
      self.data.qvel[self.non_manip_qvel_indices] = 0.0
  ```
- On every simulation step and substep, the environment explicitly forces all 12 leg joints (`self.non_manip_qpos_indices`, mapped via `qpos_idx_map`) to `0.0`.
- Because the legs are clamped perfectly straight while `base_link` is locked at $z = 0.93$ m, the feet are forcibly pinned $31.8$ mm below the floor in `self.data.xpos`, which streams directly to the Web UI.

## Summary of Root Causes & Minimal Fix Proposals

### Issue 1: Extremely Slow Arm Motion & Creeping
- **Root Cause**:
  1. `main.py:228-236` does not pass `gate_mode=args.gate_mode` to `UnifiedTeleopApp`, leaving `gate_mode="legacy"`.
  2. In `legacy` mode, `MirrorLimiter` calculates $v_{cap} = 0.7 \times 0.05 / 0.157 = 0.2229$ rad/s, choking default `normal` (0.30) and `fast` profiles.
  3. UI does not signal drag termination, leaving `app.gizmo_active_l=True` while the rate limiter cascades trickling the displacement for seconds.
- **Minimal Fix Proposal**:
  1. Pass `gate_mode=args.gate_mode` in `main.py:236` so `--gate-mode lagged` activates $0.15$ scaling ($v_{cap} = 0.669$ rad/s).
  2. Clear `gizmo_active` on mouse-up / drag end in `scene.js:113` / `cmd_targets.py`.

### Issue 2: Gripper Does Nothing
- **Root Cause**:
  1. `udp_backend.py:181` has `def send_hand: pass`, omitting `"hand"` from the UDP packet.
  2. `scripts/arm_teleop_rx.py` lacks a publisher for `/motion/control/hand_joint_command`.
  3. `sync_manager.py:85` omits `app.env.set_hand_commands` when `backend == "real-udp"`.
- **Minimal Fix Proposal**:
  1. Pack `hand` (or 2-gripper floats) into `_send_packet_now` in `udp_backend.py:155` and implement `send_hand`.
  2. Add `/motion/control/hand_joint_command` publisher to `arm_teleop_rx.py`.
  3. Call `app.env.set_hand_commands` in `sync_manager.py:85`.

### Issue 3: Real Hand Closed, UI Twin Open
- **Root Cause**:
  1. `udp_backend.py:187` hardcodes `q_hand = np.zeros(12)`.
  2. `arm_teleop_rx.py` does not subscribe to `/motion/control/hand_joint_state`.
  3. No mirroring of measured hand state into sim twin `qpos`.
- **Minimal Fix Proposal**:
  1. Subscribe to `/motion/control/hand_joint_state` in `arm_teleop_rx.py` and include `"hand"` in feedback UDP packet.
  2. Parse `"hand"` in `udp_backend.py:115` and mirror into visual twin qpos in `control_loop.py`.

### Issue 4: Legs Sunk Below Ground
- **Root Cause**:
  1. `base_link` height in `a2_ultra.xml:124` is $0.93$ m, but straight leg length is $0.9618$ m.
  2. `mujoco_env.py:217` forcibly sets all leg joints to `0.0` on every tick.
- **Minimal Fix Proposal**:
  1. Set initial leg joints from keyframe `home` with bent knees or adjust `base_link` pos to $z = 0.962$ m in `a2_ultra.xml:124`.
  2. Preserve standing keyframe leg posture in `mujoco_env.py:217` instead of zeroing.
